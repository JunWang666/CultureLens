# 0033 最短跳数均衡知识图谱布局

- 日期：2026-08-02
- 状态：已确认，实施中
- 影响范围：iOS 文化知识图谱布局与边标签显示

## 问题

现有布局把节点分成“前置、当前对象直接出边、其他”三列。它只把 `sourceID == object.id` 视为直接节点，忽略指向当前对象的普通关系，也没有计算全图最短距离。因此一个实际一跳节点可能被归入 extensions 最远列；大量 extensions 又在单列中纵向堆叠，造成画布重心右偏、上下溢出和边标签重叠。

## 决策

1. 将所有关系视为无向邻接，仅用于计算从当前对象出发的 BFS 最短跳数；箭头方向仍按原关系渲染，不改变语义。
2. 当前对象固定为 hop 0；hop 1、2、3 分别进入由内到外的同心椭圆环。任何额外关系都不能改变已经求得的最短层级。
3. 每圈半径同时受 hop 顺序和节点数量约束：后一圈必须比前一圈至少增加固定间距，节点多时按周长自动扩圈。
4. 同圈节点按稳定键排序后均匀分布，起始角按圈交错，避免所有列垂直对齐；画布围绕圆心对称扩张。
5. 双向 ScrollView 初次显示和对象变化时自动滚动到中心对象。
6. 图模式只给与当前对象相连的边显示关系标签；非中心边保留线和箭头，完整关系名称与解释继续在列表模式显示。
7. 无法从当前对象到达的孤立节点放在最外一圈，并按稳定顺序排列。

## 验证

- 单元测试覆盖：入边和出边都属于一跳；存在直达边时不会因另一条长路径被放到更远层；二跳节点位于一跳外圈；孤立节点位于最外层。
- 构建 iPhoneOS target，不启动模拟器。
