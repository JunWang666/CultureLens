# 0012 导入运动轨迹并叠加足迹地图

- 状态：已实现（2026-08-06）

## 背景

足迹页目前只显示扫描记录和知识包兴趣点。用户在徒步、跑步或骑行结束后，无法把运动 App 导出的路线带回 CultureLens，也无法在文化扫描足迹与兴趣点旁对照自己的实际行程。

## 产品范围

- 第一版导入通用 GPX 文件，兼容 `trk/trkseg/trkpt` 与 `rte/rtept`。
- 保留轨迹名称、来源文件名、导入时间、源时间、分段、坐标、海拔和点时间。
- 地图足迹模式把已保存轨迹按分段绘制为折线；暂停、GPS 断点和 GPX 原有分段不会被跨段直连。
- 足迹页工具栏提供文件导入、显示/隐藏、聚焦和删除入口。导入成功后自动切回地图并框选新轨迹。
- 暂不解析 FIT / TCX；后续格式只需新增解析适配器，地图和持久化模型不变。

## 数据与持久化

不修改 `CultureLensHistoryV3` SwiftData schema。新增文件型 `ImportedTrackStore`：

1. 文件选择器返回安全作用域 URL；store 在作用域有效期内读取内容。
2. `GPXTrackParser` 将 XML 转为 `ImportedTrack` / `ImportedTrackSegment` / `ImportedTrackPoint`。
3. 每条轨迹独立写入 Application Support 下的 `CultureLens/ImportedTracks/<uuid>.json`，使用原子写入；加载时按导入时间倒序读取。
4. 删除只移除该轨迹自己的 JSON 文件，不影响扫描历史和照片。

独立文件避免给已有 SwiftData 主库增加迁移风险，也避免单个索引文件损坏时丢失全部轨迹。归一化 JSON 是 App 内的持久副本，导入完成后不再依赖外部文件权限。

## 边界与安全

- 拒绝空轨迹、无有效经纬度的文件、超大文件和点数异常文件。
- 仅接受合法纬度 `[-90, 90]`、经度 `[-180, 180]`；无效点被忽略。
- 每条线至少包含两个点；单点段不参与地图绘制。
- 距离只在同一分段内累计，避免断点造成虚假的跨段里程。
- App 完整保存所有合法轨迹点；单段超过 10,000 点时仅对地图渲染做等距采样，并始终保留首尾点，避免超长轨迹阻塞界面。
- 导入错误在足迹页显示可理解的提示，已成功导入的其他文件不回滚。

## 验证

- 单元测试覆盖 GPX 名称/时间/海拔解析、多分段保持、路由点兼容、距离计算、无效与空文件拒绝、文件持久化和删除。
- 使用 Xcode 构建验证 `fileImporter`、MapKit 折线与工具栏菜单编译通过。
