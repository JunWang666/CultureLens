# Design 0002：人文气息的 iOS 26 Liquid Glass UI

- 状态：已确认
- 日期：2026-07-27
- 依据：CultureLens 效果稿、用户确认的 Claude 式安静人文感、Apple iOS 26 设计规范
- 影响范围：DesignSystem、应用壳层、页面布局、导航、控件、动效和无障碍

## 1. 设计命题

CultureLens 的 UI 由两个层次组成：

> 内容层像一本可以探索的文化读物，操作层像一款真正的 iOS 26 应用。

- **内容层**：温暖、安静、有纸张与墨色的实体感，承载照片、线描插画、文化解释和关系图谱。
- **操作层**：轻盈、清晰、响应触摸，使用系统导航、工具栏、Tab Bar 和 Liquid Glass。

Liquid Glass 不是视觉主题本身，而是标识“这里可以操作”的系统功能层。不能把每张文化卡片都做成玻璃。

## 2. 气质关键词

- 人文
- 安静
- 克制
- 编辑感
- 可信
- 有呼吸感
- 渐进揭示
- 现代但不科技炫技

借鉴 Claude 的部分是大留白、低噪声、自然语言引导、平静配色和长内容阅读体验；不复制 Claude 的品牌色、Logo、具体布局或组件造型。

## 3. 设计原则

### 3.1 文化内容是主角

照片、对象名称、一句话解释和文化关系应先于控件被注意到。导航和按钮保持轻量，避免抢占视觉中心。

### 3.2 一屏只回答一个主要问题

- 首页：今天想理解什么？
- 扫描页：镜头里要识别什么？
- 结果页：它是什么，为什么值得理解？
- 概念页：这个关系意味着什么？
- 文化地图：我已经理解了什么，还能去哪里？

### 3.3 渐进揭示

先给一句话判断，再给 3-5 个关系入口，最后提供长解释和来源。不能在首屏堆叠完整百科内容。

### 3.4 系统交互优先

优先使用 `TabView`、`NavigationStack`、`toolbar`、`Menu`、`sheet`、`searchable`、`PhotosPicker`、`ContentUnavailableView` 和系统分享。保留系统返回手势、键盘行为、上下文菜单和 Dynamic Type。

### 3.5 品牌来自内容，不来自重做系统控件

通过色彩、排版、留白、图像、线描关系和文案形成 CultureLens 风格。不要自定义返回按钮、底部导航、开关、菜单或弹窗来制造品牌感。

## 4. Liquid Glass 使用边界

### 4.1 应使用

- 系统 Tab Bar 和 Navigation Bar。
- Toolbar 中的收藏、分享、来源、更多操作。
- 扫描页浮于相机画面之上的关闭、闪光灯、相册入口和快门控制组。
- 临时出现的筛选、模式切换和上下文操作。
- 层级发生变化时，少量有意义的操作控件形变。

### 4.2 不应使用

- 文章正文背景。
- 每一张文化对象卡或概念卡。
- 文化关系图谱的所有节点。
- 纯装饰标签、分割线和大面积页面背景。
- 已经由系统组件自动提供玻璃效果的区域上再叠一层自定义玻璃。

### 4.3 技术规则

- 最低支持 iOS 18；iOS 18–25 保持相同信息层级和操作能力，使用系统 material 与标准按钮样式，iOS 26 再启用 Liquid Glass。
- 优先让 SwiftUI 系统组件自动获得 iOS 26 外观。
- 自定义玻璃使用 `.glassEffect`，并在所有布局和外观 modifier 之后应用。
- 多个相邻玻璃控件放入一个 `GlassEffectContainer`，避免重复容器。
- 只有可点击、可聚焦的自定义控件使用 `.interactive()`。
- 主要操作可用 `.buttonStyle(.glassProminent)`；普通操作用 `.buttonStyle(.glass)`。
- 只有视图层级真实出现或消失时才使用 `glassEffectID` 形变，不能把形变当作装饰动画。
- 同屏自定义玻璃数量必须克制；滚动列表内容不逐项使用玻璃。

## 5. Design Token

Token 先使用语义名称，实际颜色需在真机和深浅色模式中校准。

### 5.1 颜色

| Token | 浅色方向 | 用途 |
| --- | --- | --- |
| `canvas` | 温暖米白 `#F7F3EA` | 页面内容底色 |
| `surface` | 暖白 `#FCFAF5` | 文章、卡片、详情内容 |
| `inkPrimary` | 深墨蓝 `#0B2948` | 标题、关键结论 |
| `inkSecondary` | 灰蓝 `#536271` | 正文次级信息 |
| `cinnabar` | 克制朱橙 `#C7653E` | 重点、进度、选中态 |
| `antiqueGold` | 淡金 `#B99655` | 细节、关系连线、徽记 |
| `hairline` | 墨蓝低透明度 | 分割和描边 |

规则：

- 颜色全部通过 Asset Catalog 的 Any/Dark Appearance 管理。
- 深色模式不是简单反色：背景改为温暖炭黑，正文保持柔和高对比，朱橙降低发光感。
- `cinnabar` 不能成为大面积背景；它只负责节奏和焦点。
- 状态颜色优先使用系统语义色，品牌色不能取代警告、错误或成功语义。

### 5.2 排版

- 产品英文名和少量篇章标题可用系统 serif 设计，形成编辑感。
- 中文正文、按钮、标签和长篇解释使用系统字体，保证可读性与 Dynamic Type。
- 页面主标题使用 `.largeTitle` 或 `.title` 语义样式，不锁死字号。
- 正文使用 `.body`，来源和辅助信息不小于 `.caption` 的系统缩放结果。
- 行宽保持适合阅读；iPhone 上正文左右至少 20pt 内容边距。
- 数字、置信度和时间等功能信息不使用装饰字体。

### 5.3 间距与形状

- 以 4pt 为最小网格，常用节奏为 8 / 12 / 16 / 20 / 24 / 32。
- 普通内容卡圆角建议 18-24pt。
- 玻璃按钮遵循系统 Capsule 或系统推荐形状，不强行与内容卡统一。
- 最小可点击区域 44x44pt。
- 阴影极弱，仅用于内容层级；玻璃控件不叠加自制重阴影。

## 6. 核心组件

### 6.1 `CulturePageBackground`

- 温暖 `canvas` 底色。
- 可加入极低对比的纸张噪点或局部水墨晕染，但不能影响文字对比度。
- 不使用持续动画背景。

### 6.2 `EditorialHeader`

- 小型篇章眉题 + 主标题 + 一句自然语言引导。
- 大留白，不放进卡片。
- 首页可用局部线描插画，但插画不能替代可访问文本。

### 6.3 `CultureObjectCard`

- 照片或线描缩略图、对象名、时期/地域、短摘要。
- 使用 `surface` 实色或标准 material，不使用 Liquid Glass。
- 整卡可点，提供明确 pressed 状态和 VoiceOver 标签。

### 6.4 `RelationNode`

- 圆形或圆角节点，显示“历史、地域、功能、审美、相似对象”等语义。
- 选中状态用朱橙小面积强调。
- 节点连接线用淡金或低对比墨蓝。
- 图谱必须提供列表替代视图，不能只靠空间位置表达关系。

### 6.5 `SourceDisclosure`

- 在关键结论附近展示来源数量与可信提示。
- 点击后使用系统 sheet 或导航页面查看完整来源。
- “AI 生成”与“资料来源”分开表达。

### 6.6 `GlassActionCluster`

- 扫描页和沉浸式图片页使用的浮动操作组。
- 一个 `GlassEffectContainer` 管理相邻按钮。
- 主快门或确认按钮可 prominent；关闭、闪光灯、相册为普通层级。

## 7. 页面设计

### 7.1 探索首页

结构：

1. 编辑式问候：“今天，想看懂什么？”
2. 主扫描入口。
3. 最近理解的对象。
4. 推荐文化主题。
5. 个人探索进度摘要。

首页不做传统 Dashboard。主扫描入口可以是带文化对象局部图像的大型内容区，操作按钮使用系统 prominent 样式；不要把整块 Hero 做成玻璃。

### 7.2 扫描页

- 相机内容全屏延伸至边缘。
- 顶部关闭/闪光灯、底部相册/快门/帮助构成玻璃操作层。
- 识别范围使用克制的线框或角标，不持续闪烁。
- 识别中用轻量呼吸或进度反馈；支持取消。
- 权限拒绝和不可用状态使用系统内容不可用样式，并给出设置入口。

### 7.3 识别结果页

首屏顺序：

1. 对象图像。
2. “已识别”或“可能是”的可信度表达。
3. 对象名称、时期、地域。
4. 一句话文化解释。
5. 3-5 个关系节点。

收藏、分享、来源进入系统 toolbar。正文卡片保持纸张感。继续提问是显眼但不压过内容的系统操作。

### 7.4 概念详情与追问

- 像阅读一篇短文化札记，而不是聊天机器人消息流。
- 用户问题可表现为简洁引用块；回答以标题、段落、关系和来源组织。
- 默认不使用左右对话气泡。
- 底部输入或建议问题属于操作层，可使用系统输入栏与玻璃材质。

### 7.5 个人文化地图

- 首屏展示已点亮主题和最近路线。
- 图谱是探索入口，不是纯数据可视化。
- 支持按时间、地点、主题切换；切换器使用系统控件。
- 每个空间图谱都必须有可访问的列表模式。
- 空状态使用一句有温度的引导和主扫描操作。

## 8. 动效与触觉

- 动效表达层级变化、识别完成和关系建立，不表达“科技感”本身。
- 内容进入使用轻微淡入与位移，时间短、节奏稳定。
- 点亮关系节点时可有一次轻触觉与淡金连线展开。
- 扫描成功使用系统成功触觉，失败使用明确但不过度的反馈。
- 开启“减弱动态效果”时取消大范围位移、缩放和玻璃形变。
- 不使用无限脉冲、漂浮粒子或持续发光。

## 9. iOS 规范与无障碍

- 保留系统边缘返回手势，不用自定义关闭替代正常 push 返回。
- 尊重 Safe Area；沉浸内容可以延伸，文字和控件不能被遮挡。
- 支持 Dynamic Type，包括辅助功能字号。
- 支持 VoiceOver、Switch Control、键盘焦点和充分的点击区域。
- 颜色不是唯一状态表达，关系类别同时使用文字和图标。
- 验证“降低透明度”“增强对比度”“减弱动态效果”。
- 横竖屏和 iPad 虽非 Phase 1 验收重点，也不能依赖固定屏幕尺寸崩坏。

## 10. 明确禁止

- 自制仿玻璃模糊代替系统 Liquid Glass。
- 全屏玻璃、玻璃卡片瀑布流或玻璃正文。
- 自定义底部导航栏覆盖系统 Tab Bar。
- 大面积高饱和蓝紫渐变、霓虹描边、持续发光。
- 用极细浅灰字制造“高级感”。
- 把所有内容做成聊天气泡。
- 为展示动画牺牲滚动、返回、文字选择或辅助功能。
- 将效果稿中的长说明文字直接搬进 App 首屏。

## 11. 实现顺序

1. 建立语义颜色、排版、间距和形状 Token。
2. 使用原生 `TabView` + `NavigationStack` 完成 App Shell。
3. 实现 `CulturePageBackground`、`EditorialHeader`、`CultureObjectCard`。
4. 完成探索首页和识别结果静态状态。
5. 实现扫描页 `GlassActionCluster`。
6. 实现文化关系图谱与列表替代模式。
7. 接入真实数据后验证 loading、error、low-confidence 和长文本。
8. 在真机测试深浅色、动态字体、降低透明度和性能。

## 12. UI 验收标准

- 第一眼能感受到文化、人文和安静，而不是通用 AI 工具。
- 导航、返回、菜单、Tab、sheet 和输入行为符合 iOS 习惯。
- 玻璃主要出现在操作层，正文阅读区域没有玻璃干扰。
- 首页 3 秒内能找到扫描入口。
- 识别结果首屏 5 秒内能回答“是什么”和“为什么值得理解”。
- 所有核心流程在最大辅助功能字号下仍可完成。
- 深色模式不是简单反色，文字、图像和玻璃控件均清晰。
- 相邻自定义玻璃效果被合理合并，不产生明显滚动掉帧。
