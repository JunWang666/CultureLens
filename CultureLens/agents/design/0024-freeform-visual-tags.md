# 0024 — 自由视觉标签

## 背景

扫描结果目前只有主识别、备选与判断依据。它们都服务于对象 / 景点的严格知识库绑定；当照片没有合适的既有兴趣点时，仍有许多值得保留、却不应被强行映射到知识库实体的可见线索，例如「层叠出跳」「风化石材」「青绿设色」。

## 决策

1. 识别协议新增必填 `visual_tags`，含 `{ "label", "evidence" }`。若模型找不到合适的既有知识库兴趣点，必须让 `cultural_element_key` 与 `attraction_key` 均为空，并自由输出 3–6 个具体短标签；若存在合适兴趣点，则 `visual_tags` 必须为空，继续走原有识别页。`evidence` 只说明画面中可见的支撑线索；不设固定分类表，也不允许以年代、馆藏、地点或知识库正文替代视觉观察。
2. 端侧只在两个 key 都为空时接收并校验自由标签（非空、长度、去重、3–6 项）。标签不参与 key 的短 ID 还原、候选校验、对象解析或图谱归属。
3. `RecognitionResult.visualTags` 随扫描快照保存。旧快照缺少该键时解码为空数组，因此不迁移 SwiftData，也不破坏历史页恢复。
4. 当结果未绑定且带有自由标签时，`ScanResultView` 切换到独立的 `FreeformVisualTagsResultView`：只呈现当前照片、标签、可见依据与补拍建议，不显示对象详情、讲解、图谱或附近推荐。实时结果和扫描历史都可恢复此 UI；知识节点页、景点候选页与视觉备选详情永不进入该模式。

## 非目标

- 不让标签成为新的知识库实体、搜索索引、筛选条件或用户知识进度。
- 不以标签放宽候选集合，亦不恢复任何名称 / 正文模糊绑定。
- 不为标签单独发起模型请求或持久化照片以外的上下文。
