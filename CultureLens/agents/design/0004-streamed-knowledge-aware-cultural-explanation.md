# 0004 基于已有知识的流式文化背景解释

- 状态：设计中（2026-08-03）

## 背景

扫描结果页当前要求模型返回 `conclusion / why / extension / citations` 的完整 JSON，收到并解码后才一次性显示。这个结构把识别判断又重复成「一句话结论 / 为什么是它」，没有把重点放在文化背景，也无法在模型生成期间展示正文；`dynamic/chat` 首包较慢时还会触发 55 秒请求超时。

## 产品语义

- 讲解只保留两个正文层次：「文化背景」和「下一步建议」。不再解释「为什么是它」，识别证据仍由扫描结果页已有的「判断依据」卡片负责。
- 个性化来自传入的 `user_knowledge_states`：
  - `掌握`：不复述基础定义，把该节点作为比较或因果锚点。
  - `理解`：只补当前对象与已理解节点之间的关系和缺口。
  - `接触`：允许一句话唤起，但补齐必要基础。
  - 未加入图谱：从最少必需背景讲起，避免假设用户已经知道术语。
- 个性化通过内容选择、解释深度和衔接方式体现，不输出「根据你的画像」一类元话术。页面显示本次传入的已有知识数量，让用户知道解释依据了其文化图谱。
- 下一步建议限制为 1–2 条简短、可执行的观察或追问方向，不再泛化为大段「向外延展」。

## 数据流与接口

1. `CultureExplanationService` 继续组装识别对象、图谱邻居、知识库片段、现场上下文和用户知识状态，但返回 `AsyncThrowingStream<ChatStreamEvent, Error>`。
2. `LLMGatewayClient` 复用聊天的 SSE `/chat/completions` 通道；解释请求发送 `reasoning_effort: low`，并使用 180 秒流式请求超时。识别请求的非流式超时保持不变。
3. 模型直接输出 Markdown，固定结构为：
   - `## 文化背景`
   - `## 下一步建议`
   - `## 引用来源`
4. 流式阶段将「引用来源」之前的累计 Markdown 快照交给 `SwiftStreamingMarkdown`；完成后复用引用解析器，将引用区转成 `KnowledgeCitation` 卡片。
5. `ScanResultView` 为每次请求创建稳定的 `GrowingMarkdownSource`，避免 token 到达时重建 `StreamedMarkdownView`。切换扫描会取消旧任务并结束旧 source，防止串流写入新页面。

## 失败与兼容

- 首个正文 token 前显示「正在按你的已有知识整理文化背景」；若上游发送 reasoning token，只更新等待文案，不展示思考内容。
- 已收到部分正文后连接失败时保留已生成内容，并提供重试；尚未收到正文则显示原有失败卡片。
- 网关忽略 `stream: true` 并返回完整 JSON completion 时，沿用现有渐进揭示回退。
- 演示数据不调用网关，直接生成同样两段式 Markdown 与本地引用。

## 验证

- 单元测试覆盖解释 prompt 的知识状态分层规则、固定 Markdown 结构、低思考强度请求参数和引用区解析。
- Debug 构建与现有单元测试通过；真机需验证首包等待、长响应、滚动布局和中途断网后的部分内容保留。
