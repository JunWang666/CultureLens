# Design 0004：可解释的有向文化知识图谱

- 状态：已确认，进入实现
- 日期：2026-07-29
- 影响范围：领域模型、样例知识、识别结果协议、关系图谱 UI、概念导航和测试

## 1. 问题

现有关系区只把 `CultureObject.concepts` 均匀摆在对象周围。它没有保存或显示边，因而无法回答：

- 两个节点为什么相关？
- 关系从哪里指向哪里？
- 理解当前对象需要先懂什么？
- 当前对象如何继续连接到礼仪、制度、技术或审美？

视觉上的放射布局不等于知识图谱。本轮必须把关系作为一等数据。

## 2. 图谱模型

CultureLens 使用有向属性图：

- 节点：一个 `CultureObject` 加若干 `CultureConcept`。
- 边：`CultureRelation(sourceID, targetID, kind, explanation)`。
- 方向：箭头从前提、主体或影响来源指向被解释的目标。
- 标签：每条边必须显示 `RelationKind`，详情列表同时显示解释文本。

`CultureObject` 新增 `relations: [CultureRelation]`。概念继续作为对象内的值类型节点；首版不引入
SwiftData 图数据库。

新增概念类别：

- `基础知识`：理解对象之前需要掌握的结构、术语或观察方法。
- `制度`：礼制、等级、规范及组织方式。

新增关系：

- `理解前先懂`：前置知识指向待理解节点。
- `体现`：对象或概念指向其呈现的观念/制度。
- `受规制于`：对象指向约束其形制或使用的制度/规范。
- `解释`：一个概念为另一个概念提供因果或语义说明。

保留既有的“产生于、位于、用于、象征、受到影响、相似于、组成”，供其他对象使用。

## 3. 斗拱样例拓扑

首个完整样例应至少表达：

```text
木构架基本构成 ──理解前先懂──▶ 斗拱
榫卯与节点受力 ──理解前先懂──▶ 斗拱
铺作、出跳与材分 ──理解前先懂──▶ 斗拱

斗拱 ──用于──▶ 承托出檐与传力
斗拱 ──受规制于──▶ 官式营造规范
斗拱 ──体现──▶ 建筑等级
建筑等级 ──解释──▶ 礼制秩序
斗拱 ──体现──▶ 层叠与节奏
```

“礼制秩序”节点必须明确说明：斗拱只是判断建筑身份的一项线索，不能脱离屋顶形制、尺度、色彩、
空间位置和时代背景单独判定等级。

## 4. 图形布局与交互

图谱采用稳定的分层布局，不使用随机力导向：

1. 左列：通过“理解前先懂”连入对象的基础节点。
2. 中列：当前文化对象。
3. 右列：对象直接连接的功能、制度、历史与审美节点。
4. 延伸列：由右列继续连接的二阶概念，例如“建筑等级 → 礼制秩序”。

画布允许水平和垂直拖动。所有边包含箭头和短关系标签；节点可点击进入概念详情。图谱顶部提供一句
“从左到右阅读”的说明，并显示前置知识数量。

列表模式是同一份图数据的等价表达，每行显示：

> 来源节点 → 关系类型 → 目标节点

下方显示边的解释，不能退化为没有关系的概念列表。

## 5. 数据与服务边界

- 内置斗拱样例提供完整节点与边，用于 UI 骨架和稳定测试。
- 其他样例至少提供对象到概念的明确边。
- 远端识别算法不在本轮实现。BFF 暂时返回空 `relations`，客户端显示“关系资料不足”，不得根据
  `ConceptKind` 猜测或伪造边。
- 后续知识服务接入时，必须返回经过来源约束的关系三元组，再进入同一 UI。

## 6. 验证

- 每条关系的 `sourceID`、`targetID` 都能解析为当前对象或其概念。
- 斗拱至少包含一个前置知识路径和一个通往礼制秩序的二阶路径。
- 图谱模式能看到节点、箭头和边标签；列表模式显示同一批关系。
- 点击概念节点仍可进入详情。
- 空关系对象有明确降级，不把概念集合伪装成图谱。
