# 0003 结果页图谱预览、全屏交互与缩放

- 状态：已设计（2026-08-03）

## 背景

扫描结果页内嵌的关系图当前直接使用双向 `ScrollView` 和可导航节点。用户在阅读结果页或上下滚动时，图谱会截获拖动和节点点击；画布较大时也难以在有限高度内先看清整体关系。缩放能力缺失，进入密集关系后只能反复横纵拖动。

## 交互边界

- 只有扫描结果页改为「静态预览」：默认展示完整图谱的等比缩略图，不响应拖动、节点点击、列表切换或缩放。
- 静态预览整体是单一按钮。点击任意位置以 `fullScreenCover` 展开图谱，避免结果页导航栈被大画布布局影响。
- 全屏态才启用横纵拖动、概念节点跳转、图谱 / 列表切换和缩放。
- 对象详情与历史详情继续使用原有内嵌交互态，避免本次结果页交互调整扩大行为变化范围。

## 组件结构

`CultureRelationGraphView` 增加展示方式：

- `inlineInteractive`：默认值，保持原内嵌交互行为。
- `expandablePreview`：扫描结果页使用，只画静态预览并负责弹出全屏。
- `fullscreen`：组件内部使用，承载完整交互和关闭按钮。

三种方式共享 `GraphLayout`、边线、对象节点和概念节点渲染，避免预览与全屏出现不同节点或不同布局。预览不为节点包裹 `NavigationLink`，同时关闭子视图命中测试；外层只保留「展开全屏」按钮。

全屏使用独立 `NavigationStack`。由于全屏 cover 不继承结果页的类型化导航路径，组件在该栈内只处理自己产生的概念路由，保证概念节点仍可打开详情。

## 缩放模型

- 使用 SwiftUI `MagnifyGesture` 处理双指缩放，手势中的临时倍率与已提交倍率分离，结束后再钳制并保存。
- 缩放范围为 50%–250%，工具栏提供减小、百分比复位、放大三个可访问按钮；每次按钮调整 25%。
- 首次进入全屏，根据画布和可用视口计算 `min(widthRatio, heightRatio, 1)`，再钳制到允许范围，使中小型图谱尽可能完整出现且不会自动放大超过 100%。
- 缩放后的内容同时调整外层布局尺寸，并以左上角为锚点，令双向 `ScrollView` 获得正确可滚动范围；拖动和缩放只存在于全屏图谱态。

缩放计算提取为无状态 `GraphZoom` 纯函数，便于单元测试覆盖最小 / 最大边界、步进和适配视口算法。

## 性能

- 静态预览沿用一次性确定性 `GraphLayout`，只做比例变换，不启动物理模拟、定时器或逐帧布局。
- 预览与全屏不会同时持续交互：全屏由按需 cover 创建，关闭后释放其手势与滚动状态。
- 双指手势只更新一个标量；节点数量、关系数量和图布局均不随缩放重算。
- 使用现有图谱节点规模，不引入图片快照或第二套关系查询。

## 验证

- 单元测试覆盖缩放钳制、按钮步进和视口适配。
- Xcode Debug 构建验证预览 / 全屏分支、独立概念导航及 `MagnifyGesture` 编译。
- 人工真机检查：结果页纵向滚动不被图谱截获；点击预览进入全屏；全屏可拖动、双指缩放、按钮缩放、复位和进入概念详情。
