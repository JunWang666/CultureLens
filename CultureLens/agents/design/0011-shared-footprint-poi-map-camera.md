# 0011 足迹与兴趣点共享地图相机

- 状态：已实现（2026-08-06）

## 背景

足迹页的「地图足迹」和「兴趣点」原先分别创建 `Map`，并分别持有相机、可见范围和搜索区域。切换模式会销毁当前底图、创建另一张底图，并恢复另一套相机状态，造成地图位置和瓦片明显跳跃。

## 设计

- 两个地图模式复用同一个 `Map`、`MapCameraPosition`、当前 `MapCamera`、可见跨度和搜索区域。
- 模式切换只替换足迹或兴趣点标注，不替换底图视图。
- 足迹标注与兴趣点标注在 `MapContentBuilder` 中使用两个固定、彼此独立的 `ForEach` 槽位；切换模式只让对应数据源变为空，避免 MapKit 把上一模式的标注视图复用到另一类坐标上。
- 从一种地图模式切到另一种地图模式前，把 `.automatic` 固定为屏幕上实际相机，并禁用这次状态切换的动画，防止 MapKit 根据新标注集合自动重新取景。
- 时间线仍是独立内容；从时间线返回地图时沿用离开前的共享相机。
- 兴趣点载入中、不可用或为空时，地图继续保留，只在左上角显示状态提示。
- 地点搜索、定位和 3D 俯视都操作这套共享相机，因此切换标注层后保持同一中心、缩放、朝向和俯仰角。
- 兴趣点聚合读取共享地图的实时可见跨度，但把参与距离计算的跨度上限限制为 `0.05°`。这样近距离缩放时仍会合并屏幕上难以点选的相邻标注，而足迹或 GPX 把相机拉到很远时，不会把城市内互不相干的兴趣点错误堆成一组。
- 兴趣点名称来自 attraction，因此点击目标必须优先解析为与 attraction 同 slug 的「看点」根元素；同坐标第一条 introduction 可能是文化历史上下文，不能用它的 `culturalElementId` 决定导航。只有景点没有可解析看点根元素时，才回退到 introduction 元素。

## 验证

- iOS Simulator Debug build 编译通过。
- 手工验证应覆盖：拖动/缩放/旋转地图后往返切换「地图足迹」与「兴趣点」，底图中心、缩放、朝向和俯仰角均不变化，仅标注替换。
- 回归验证应先把足迹地图缩放到整条 GPX 或更大范围，再切到兴趣点；兴趣点保持原位置，只有同址或约数百米内的点允许聚合。
- 单测覆盖「三潭印月」地图点：即使第一条现场介绍绑定「西湖月景与倒影营造」，点的导航 UUID 仍必须解析到「三潭印月」看点根元素。
