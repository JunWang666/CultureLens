# Design 0010：PVE 内部服务网络

- 日期：2026-07-30
- 状态：已实施并验证
- 影响范围：PVE `192.168.3.101`、LXC 113、VM 101、VM 107、VM 108

## 背景

CultureLens 后端运行在 VM 108。Cloudflare Tunnel、个人服务和 AI 服务分别运行在
LXC 113、VM 101、VM 107。四个实例需要通过 PVE 内部二层网络直接互访，避免服务间
流量依赖家庭 LAN 地址或 LAN DHCP 租约。

PVE 已存在内部网桥 `vmbr1`，地址为 `10.0.0.1/24`，并已为
`10.0.0.0/24` 配置经 `vmbr0` 的 IPv4 转发与 NAT。VM 101 已连接 `vmbr1`，
来宾系统内已有静态地址 `10.0.0.127/24`。本次复用该网桥和网段，不新增网段。

## 决策

四个实例均保留现有 `vmbr0` 网卡和默认路由，新增或复用一张只连接 `vmbr1` 的
VirtIO/veth 网卡。内部网卡不设置默认网关，以防改变现有外网出口和远程管理路径。

地址分配如下：

| 实例 | PVE ID | 内部地址 |
| --- | ---: | --- |
| PVE 网桥 | - | `10.0.0.1/24` |
| DebainAI | 107 | `10.0.0.107/24` |
| CultureLens | 108 | `10.0.0.108/24` |
| cloudflared | 113 | `10.0.0.113/24` |
| DebianOwnUse | 101 | `10.0.0.127/24`（保留既有地址） |

除 VM 101 的既有地址外，新地址使用 PVE ID 作为末段，降低人工运维时的映射成本。

## 安全与运行边界

- 不删除、不替换任何现有网卡。
- 不改变现有默认路由、DNS、LAN DHCP 或 Cloudflare Tunnel 凭据。
- `vmbr1` 不连接物理端口，只在 PVE 内形成隔离二层网络。
- VM 101 实施前处于关机状态；为验证配置可短暂启动，验证后恢复关机。
- PVE 侧配置和来宾系统网络配置均需持久化，重启后地址保持不变。

## 验证

1. PVE 配置中四个实例均存在连接 `vmbr1` 的第二网卡。
2. 来宾系统内部网卡为 `UP`，并持有上述静态地址。
3. 从每个运行实例 ping 其余三个内部地址；VM 101 验证完成后恢复关机。
4. 验证各实例原有 `vmbr0` 地址和默认路由未改变。
5. 验证 cloudflared 服务仍在运行，CultureLens 后端健康检查仍可访问。

## 回滚

- 从 LXC 113、VM 107、VM 108 删除新增的第二网卡。
- 删除三台实例中新建的内部接口配置文件。
- VM 101 保留实施前已存在的 `vmbr1` 网卡和 `10.0.0.127/24` 配置。
- 不删除或重建既有 `vmbr1`。

## 实施结果

2026-07-30 已在 PVE `192.168.3.101` 完成：

- 复用并启用 `vmbr1`，保持 `10.0.0.1/24` 和既有 NAT 配置。
- VM 107、VM 108 新增连接 `vmbr1` 的 VirtIO `net1`；来宾系统使用
  `/etc/network/interfaces.d/10-pve-internal` 持久化 `ens19` 静态地址。
- LXC 113 新增连接 `vmbr1` 的 `eth1`，由 PVE LXC 配置持久化静态地址。
- VM 101 保留既有 `net1` 和 `10.0.0.127/24`，验证时短暂启动并在结束后恢复关机。
- 四个实例的 12 条双向 ping 路径全部成功；原有 LAN 网卡与
  `192.168.3.1` 默认路由均未改变。
- `cloudflared-h2.service` 保持 enabled、active；cloudflared 经 `eth1`
  到 `10.0.0.108` 的路由和 ping 已验证。

2026-07-30 已在 VM 108 安装并启用 Docker 26.1.5，`culturelens` 生产容器监听
`0.0.0.0:8080` / `[::]:8080`，并使用 `unless-stopped` 重启策略。容器内、LAN
地址 `192.168.3.138:8080` 和内部地址 `10.0.0.108:8080` 的 `/health` 均返回
`{"status":"ok"}`，Docker 健康状态为 `healthy`。

2026-07-30 外网实测确认 `cl.codight.online` 已经由 Cloudflare 路由到 CultureLens
API：HTTP `/health` 301 跳转 HTTPS，HTTPS `/health` 返回 200 和
`{"status":"ok"}`；空的 `POST /v1/recognitions` 返回服务约定的 400
`invalid_request` 与 request ID，证明健康检查和 API 路由均已接通。
