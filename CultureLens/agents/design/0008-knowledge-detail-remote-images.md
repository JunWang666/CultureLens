# 0008 知识详情在线图片展示

## 背景

知识包的 `RichTextDocument.Block` 已支持 `type: "image"`、HTTPS `url` 与可选
`caption`，`RichTextBlocksView` 也有基础 `AsyncImage` 分支；但当前链路有两个缺口：

1. 图片加载态与失败态只是临时占位，失败后不能由用户重试，也没有明确的无障碍描述。
2. 英文详情在缺少完整 overlay 时会把正文交给 `KnowledgeTranslationService`，翻译结果被重建为
   纯段落，源知识文档里的图片块随之丢失。

本设计只实现展示能力，不修改知识包内容、不添加示例数据或 Mock。

## 目标

- 详情页能够展示知识包正文中的公开 HTTPS 图片资源。
- 图片有稳定的加载、成功、失败与重试状态。
- 图片保持宽高比，不撑破 iPhone 单栏或 iPad 分栏布局。
- `caption` 同时作为可见图注与默认无障碍描述。
- 切换语言或走即时翻译时，源文档图片仍按原顺序保留。
- 没有图片块的旧知识条目保持现有布局和行为。

## 数据契约

继续使用现有 RichText block，不新增第二套图片字段：

```json
{
  "type": "image",
  "url": "https://...",
  "caption": "..."
}
```

- `url` 必须是可匿名读取、直接返回图片内容的 HTTPS 地址。
- `caption` 可选；存在时用于图注和 VoiceOver。
- 图片块所在的 `blocks` 顺序就是详情页展示顺序。
- 图片不进入 `plainText`，因此不改变识别候选、Prompt 或摘要。

## 展示与数据流

1. `LocalizedKnowledgeBlocksView` 读取知识库源文档。
2. 源语言直接展示源文档。
3. overlay 或即时翻译返回本地化文档后：
   - 若本地化文档已有图片块，以本地化文档为准；
   - 若没有，则把源文档图片块按源顺序插入本地化正文首段之后。
4. `RichTextBlocksView` 将图片块交给独立的远程图片子视图：
   - 加载中显示固定高度进度态；
   - 成功后按图片原比例适配栏宽；
   - 失败后显示错误态与重试按钮；
   - 图注位于图片下方。

## 兼容性与失败策略

- 空 URL、无效 URL 或非图片 block 不进入远程图片分支。
- 网络失败只影响单张图片，不阻断正文与详情页其他区域。
- SwiftUI view 生命周期结束时，`AsyncImage` 的请求随视图取消。
- 不做磁盘媒体缓存、全屏图片浏览或预取；后续图片规模增长后再独立设计。

## 验证

- 编译 App 与单元测试 target。
- 运行现有 `imageBlockDecodesAndRoundTrips`，确保数据契约未变。
- 以真实知识包做无图片回归：详情页布局不新增空白区域。
- 待真实在线图片数据提供后，在真机验证加载、失败重试、动态字体与 VoiceOver。
